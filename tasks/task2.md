# 任务2
## Agent 为什么能够读取文件、修改代码，而普通聊天 AI 通常不能？
普通聊天AI只有大模型本身，仅能做文本生成；Agent在大模型之外额外对接了文件读写、代码编辑等外部工具，模型输出调用指令，由外部程序实际完成读文件、改代码操作，模型本身并不直接操作本地文件。

## Tool 在 Agent 中起到了什么作用？
Tool（工具）是Agent和真实世界交互的接口。大模型本身只能输出文本，工具让Agent可以执行外部动作，例如读文件、运行代码、联网查询、调用终端；模型负责思考判断什么时候调用工具，工具负责落地执行真实操作，把执行结果返回给大模型继续推理。

## 为什么项目需要给 Agent 配置一份类似“员工手册”的规则？
用来约束Agent的行为边界，告诉Agent任务目标、禁止做什么、做事流程、输出格式、出错处理方式。大模型本身是无约束的，手册类系统提示可以减少Agent乱操作、偏离任务、做危险行为，让它按照项目预期规范完成任务。

## Agent 为什么可能“忘记”之前说过的内容？Agent的额度怎么样计算？
- 忘记原因：Agent对话有上下文窗口长度限制，历史消息全部会占用token；当历史对话、工具返回结果太多，超出窗口上限，早期的历史内容会被丢弃截断，于是表现为“忘记”。
- 额度（token）计算：输入（系统提示+历史对话+工具返回结果+当前提问）+ Agent输出内容，全部统一折算为token，总token不能超过模型上下文窗口的最大额度。

## 如果一个 Agent 可以随便执行任何终端命令，会有什么风险？
Agent有可能生成破坏性命令：删除文件、篡改系统配置、窃取本地隐私数据、下载恶意程序、访问内网资源；一旦执行会造成文件丢失、系统损坏、信息泄露，甚至被攻击者利用，造成安全事故。因此必须做命令白名单、权限限制。
